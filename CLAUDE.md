# CLAUDE.md

Правила роботи над цим репозиторієм. Claude Code читає цей файл автоматично
на початку кожної сесії.

**Контент сайту — англійською. Спілкування з людиною — українською.**

## Що це

STARPaw.net — статичний англомовний фан-сайт про Warrior Cats.
Чотири розділи: Roasts, Files, Atlas, Herbs.

Хостинг — Cloudflare Pages. Мерж у `main` публікує сайт автоматично.
Кожен pull request отримує власне посилання попереднього перегляду.

## Файли-джерела

Перед роботою прочитати:

- `SPEC.md` — технічне завдання. Маршрути, тексти, структура. Головний документ.
- `DESIGN.md` — дизайн-система. Кольори, шрифти, компоненти.
- `HANDOFF.md` — поточні задачі й правила обміну між інструментами.

Якщо `SPEC.md` і `DESIGN.md` суперечать одне одному — не вгадувати. Записати
питання в `HANDOFF.md`, секція `# ПИТАННЯ`, і зупинитись.

## Жорсткі правила

1. **Ніякої збірки.** Без npm, package.json, Node, генераторів статики,
   фреймворків, препроцесорів і залежностей. Тільки HTML, CSS і звичайний JS.
   Cloudflare Pages публікує репозиторій як є, без build command.
2. **Без зовнішніх сервісів шрифтів.** Шрифти беруться зі стека, вказаного
   в `SPEC.md`.
3. **Не міняти структуру файлів,** описану в `SPEC.md`. Нових розділів не
   створювати без прямої вказівки.
4. **Один PR — одна задача.**
5. **Ніколи не пушити напряму в `main`.** Тільки робоча гілка й pull request.
6. **Не видаляти контент** без прямого прохання.

## Хто власник якого файлу

Редагує тільки власник. Решта читають.

| Файл | Власник |
|---|---|
| `SPEC.md` | ЧАТ |
| `CLAUDE.md` | ЧАТ |
| `DESIGN.md` | ДИЗАЙН, руками КОДу |
| `HANDOFF.md` | усі, кожен у своїй секції |
| `assets/**`, сторінки `*.html` | КОД |

`source/` — сирий довідковий матеріал. Читати тільки якщо бракує деталей,
і ніколи не тягнути звідти цілі файли в контекст.

## Як розмовляти з людиною

Зазвичай це людина без технічних знань. Не показувати команди, шляхи до
файлів і git. Пояснювати звичайними словами, коротко. Якщо щось зламалось —
не вставляти помилку, а сказати: «Щось пішло не так, варто покликати тата».

## Як завершувати роботу

1. Коміт у робочу гілку.
2. Відкрити pull request.
3. Дописати зроблене в `HANDOFF.md`, секція `# ЗРОБЛЕНО`.
4. Сказати людині так:

> Готово. Ось посилання на попередній перегляд — подивись, і якщо все добре,
> натисни зелену кнопку Merge. За хвилину з'явиться на сайті.
